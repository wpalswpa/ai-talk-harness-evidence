# 002. 중단 시점을 학습 모델로 자동화하지 않기로 했다

2026-09-23. 의논을 언제 끝내고 결과물을 쓸지(STOP)와 더 의논할지(CONTINUE)를 학습 모델로 정할지 실험으로 판정했다.

## 미리 정한 규칙

상수 예측(항상 멈춤 또는 항상 계속)보다 나은 학습 모델이 없으면 운영 판정에 도입하지 않는다. 이 규칙과 평가 기준은 최종 실행 결과보다 먼저 커밋했고, 결과를 보고 바꾸지 않았다.

## 실험

- 기록된 대화 상태 12개(과제 5종, 참여자 Groq + Claude)마다 STOP(지금 작성)과 CONTINUE(남은 의논을 설정한 최대 바퀴까지 마친 뒤 작성)를 돌렸다. 두 갈래는 같은 평가 기준과 같은 작성·채점 모델을 썼다.
- 라벨은 상태 10건(비교자 호출 실패 2건 제외).

## 결과

| 항목 | STOP | CONTINUE |
|---|---|---|
| 평균 모델 호출 | 2.0회 | 5.6회 |
| 평균 소요 | 52초 | 109초 |
| 평가 점수 | 12개 중 10개 상태에서 같거나 높음 | |

- 중단 시점 학습 모델(로지스틱 회귀, 과제 계열을 하나씩 빼는 교차검증)의 정확도는 50%로, "항상 멈춤"의 60%를 넘지 못했다(라벨 10건). 원래 대화에 기록된 사회자의 종료 값은 70%(1건은 호출 실패 뒤 기본값), 결과 비교에 쓴 평가 전용 모델의 종료 판정은 30%였다.
- 같은 상태를 두 번 라벨링한 7건 중 3건만 같았다(43%). 작업 폴더 격리 전후의 다른 조건 비교라 재현율의 상한으로 읽지 않는다.

## 판정

라벨 10건에서 로지스틱 회귀 모델을 만들어 평가했으나(정확도 50%) "항상 멈춤" 60%를 넘지 못해, 규칙대로 운영 판정에는 도입하지 않았다. 종료는 기존대로 정한 바퀴 수(기본 2, 1~4) 안에서 사회자 판정이 정한다. 실험 기록에는 "한 바퀴 의논 뒤 작성"을 다음 규칙으로 적었지만 서버에는 반영하지 않았고, 한 바퀴는 이 실험에서 따로 비교한 값도 아니다. 상태가 더 쌓여 상수 예측을 넘는 모델이 나오면 그때 다시 본다.

## 한계

상태 12·라벨 10은 작은 표본이다. 품질 비교는 LLM 채점(블라인드)이며 사람 평가가 아니다. 과제가 짧다. 실험 코드는 원본 정리 때 삭제되어 원본 git 이력에만 있고 이 저장소에는 없다. 점수·호출·소요는 원본 DB `session_outcomes`·`model_calls`에서, 라벨·정확도는 실험 출력 파일에서 다시 센 값이며, 30%는 당시 실험 표의 값이다.
